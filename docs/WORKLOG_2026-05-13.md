## Penjelasan (Kenapa Day 2 Penting)

**Masalah sebelumnya:**
`main.py` adalah file monolitik — semua logic endpoint (chat, execute, auth, cache, export, schema)
ada di satu file. Tidak ada batas yang jelas antara "request handling" dan "business logic".
Sulit ditest, sulit diubah tanpa risiko memecah hal lain.

**Yang diselesaikan:**
Day 2 tidak langsung memindahkan kode — tapi **memetakan dulu** (audit) blok mana yang harus
dipindah ke mana. Ini penting agar migrasi bertahap tidak berantakan.

Hasilnya: dokumen extraction plan + skeleton kosong `services/`:
```
services/
  __init__.py
  chat_service.py   ← akan jadi rumah logic chat
  app_services.py   ← akan jadi container dependency
```

**Kenapa skeleton dulu, bukan langsung isi?**
Agar Day 2 tetap non-breaking. Skeleton bisa di-commit dan di-push tanpa risiko merusak
endpoint yang sedang berjalan. Isi sebenarnya baru dimasukkan di Day 3.
